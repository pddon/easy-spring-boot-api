# 简介
#### 1、简介

> 此项目用于演示如何使用easyapi提供的接口防重复提交功能。使用防重提交功能，只需要在需要防重的接口上添加`@RequiredNoRepeatSubmit`注解即可。主要有以下内容：
>
> 1. 防重复提交码模式
>
>     - 自定义防重复提交码
>
>         > 自定义防重复提交码需要调用者保证防重复提交码的全局唯一性，推荐结构：userId+timestamp
>
>     > timestamp在数据更新后才允许更新
>
>     - 使用sign作为防重码
>
>         > 如果接口开启了数字签名，则可以直接使用数字签名值sign作为防重复提交码，sign的算法自然就保证了防重码的唯一性
>
> 2. 开启接口防重提交功能，避免因用户误操作重复提交而导致的多次相同的脏数据
>
> 对于一些新增数据的接口通常需要进行接口的防重复提交保护，如：用户账号注册、用户下单、用户发帖等等类似的应用场景。
>
> 防重复提交主要应用场景是避免用户短时间内由于误操作导致同一份数据被保存多次所带来的问题，如果被保存的数据内容存在唯一标识限制则可以选择不使用防重复提交，在业务侧保证数据的唯一性即可。
>
> 注意：防重复提交只能防止短时间内用户的误操作导致插入重复数据的问题，如果需要数据的唯一性还是需要在业务中自行处理。

## 4 演示代码解析

### 4.1 接口防重提交使用示例

> 业务异常的使用主要分两种应用场景：
>
> 1. 开启验证请求数据数字签名的接口，再开启防重复提交可以选择使用数字签名`sign`作为防重码
> 2. 未开启数字签名的接口，需要调用者自己生成一个全局唯一的防重码
>
> 示例代码如下所示。

> 差异说明：原文档示例的`TestDenyRepeatSubmitController`（`POST testUserAccountRegistNoRepeatSubmit`/`testUserAccountRegistNoRepeatSubmitBySign`，请求体为`UserInfoDto`）在本模块中不存在，实际接口为`RepeatSubmitController`（包`com.pddon.framework.demo.easyapi.repeat`，路径前缀`/repeat`），使用GET请求和`orderId`查询参数，没有`UserInfoDto`，也不再有模拟3秒耗时的逻辑。

* 接口源码`RepeatSubmitController.java`

```java
package com.pddon.framework.demo.easyapi.repeat;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import com.pddon.framework.easyapi.annotation.RequiredNoRepeatSubmit;
import com.pddon.framework.easyapi.annotation.RequiredSign;
import com.pddon.framework.easyapi.consts.DenyRepeatSubmitType;
import com.pddon.framework.easyapi.consts.SignScope;

/**
 * 接口防重复提交示例。
 */
@RestController
@RequestMapping("/repeat")
public class RepeatSubmitController {

    /**
     * 客户端主动生成 repeatCode（全局唯一），服务端据此防止重复提交。
     * 需要同时携带 timestamp 系统参数。
     */
    @GetMapping("/generateToken")
    @RequiredNoRepeatSubmit(mode = DenyRepeatSubmitType.GENERATE_TOKEN)
    public String generateToken(@RequestParam String orderId) {
        return "submitted:" + orderId;
    }

    /**
     * 使用数字签名作为防重码：同一 timestamp + 同一请求内容生成的 sign 相同。
     * 同时开启验签校验。
     */
    @GetMapping("/sign")
    @RequiredSign(scope = SignScope.REQUEST)
    @RequiredNoRepeatSubmit(mode = DenyRepeatSubmitType.USE_SIGN)
    public String sign(@RequestParam String orderId) {
        return "submitted:" + orderId;
    }
}
```

### 4.3 失败释放防重码（默认行为）

> `easyapi.no-repeat-submit.release-on-failure`默认`true`，语义为：
>
> * 业务方法正常返回 → 提交码标记为已提交（`used`），同码再次请求返回`UNIQUE_TOKEN_USED(130007)`；
> * 参数校验失败、验签失败、`BusinessException`、系统异常等失败路径 → 释放提交码，客户端修正后可用同一个码立即重试；
> * 并发重复请求被`UNIQUE_TOKEN_USING(130006)`拒绝时，不会释放其他请求已持有的提交码（释放前校验码的所有权）。
>
> 如需回退到旧行为（无论成功失败都标记已提交），配置`release-on-failure: false`即可。

* 失败后可立即重试的示例接口（`RepeatSubmitController`）

```java
    /**
     * 业务异常：抛出 BusinessException，用于演示失败后释放提交码。
     */
    @GetMapping("/fail")
    @RequiredNoRepeatSubmit(mode = DenyRepeatSubmitType.GENERATE_TOKEN)
    public String fail(@RequestParam String orderId) {
        throw new BusinessException(ErrorCodes.BUSINNES_ERROR);
    }

    /**
     * 系统异常：抛出运行时异常（HTTP 500），同样释放提交码。
     */
    @GetMapping("/error")
    @RequiredNoRepeatSubmit(mode = DenyRepeatSubmitType.GENERATE_TOKEN)
    public String error(@RequestParam String orderId) {
        throw new IllegalStateException("boom:" + orderId);
    }
```

* 请求与结果

```shell
# 第一次：code=200000（业务异常），提交码被释放
curl "http://localhost:8083/repeat/fail?appId=webApp&channelId=default&orderId=retry-1&repeatCode=token-retry&timestamp=1700000000000"

# 用同一个 repeatCode 立即重试：仍然进入业务逻辑（依旧返回业务异常码），说明码未被占用
curl "http://localhost:8083/repeat/fail?appId=webApp&channelId=default&orderId=retry-1&repeatCode=token-retry&timestamp=1700000000000"

# 换一个成功接口验证“成功后同码被占用”的语义
curl "http://localhost:8083/repeat/generateToken?appId=webApp&channelId=default&orderId=ok-1&repeatCode=token-ok&timestamp=1700000000000"
curl "http://localhost:8083/repeat/generateToken?appId=webApp&channelId=default&orderId=ok-2&repeatCode=token-ok&timestamp=1700000000000"  # code=130007
```

> 端到端用例见`RepeatSubmitEndToEndTest`（业务成功、业务异常、系统异常、并发同码、默认值）与`RepeatSubmitReleaseDisabledEndToEndTest`（`release-on-failure=false`回退旧行为）。
