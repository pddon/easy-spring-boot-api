# 简介
> 此项目用于演示如何使用easyapi提供的缓存切面对方法调用进行拦截。调用方法前先检查是否存在接口结果缓存，如果不存在则执行方法业务，完成后再缓存业务结果，以备后续查询。其实spring已经提供了缓存相关注解，但是我在使用过程中总感觉用起来不方便，故此实现一套简单实用的缓存管理机制。主要有以下内容：
>
> 1. 对查询结果及时性要求不高的方法调用，可以为方法设置较短时效的结果查询缓存
> 2. 查询非用户级、变化频率低但使用很频繁的热点数据，可以设置较长时效的结果查询缓存
> 3. 方法缓存更新
>     * 方法结果缓存失效拦截器
>     * 手动调用缓存管理器进行失效
> 4. 手动管理业务缓存
> 5. 使用自定义的缓存管理器，以自定义redis缓存管理器为例
> 6. 服务缓存状态监控和管理
>
> 使用方法：
>
> * 在需要缓存业务结果的方法上添加`@CacheMethodResult`注解即可实现接口结果的缓存；
> * 如果更新数据的方法需要及时的清除接口查询缓存，则在方法上添加`@CacheMethodResultEvict`注解即可；
> * 也可以通过`CacheManager`手动管理缓存;

> **本地缓存并发说明（本次优化）**：默认仍使用全局锁，保持原有行为。若确认业务可接受弱一致，可开启无锁读写的可选配置：
>
> ```yaml
> easyapi:
>   local-cache:
>     lock-free: false #默认false；true时set/remove/clear不再持有全局锁
>     # 注意：lock-free模式下并发写入同一key不同过期时效时，可能短暂同时存在于两个过期桶；
>     # 写入完成后会清理其它桶中的副本；对强一致清理有要求时保持默认false
> ```
>
> 开启后`set/remove/clear`依赖`ConcurrentHashMap`与Guava Cache的线程安全，创建新的过期桶时仍使用双检锁。极端情况下，同一key被并发写入不同过期时效的瞬间，可能短暂同时存在于两个过期桶中；写入完成后`set`会清理其它桶中的副本，`remove(key)`会清理所有桶，`clear(null)`会清空全部桶。极端交错下也可能两份副本被并发写入方互相清理而短暂缺失（表现为一次缓存未命中并重新计算，不会返回错误数据）。对缓存清理强一致有严格要求时，请保持默认配置。

## 4 演示代码解析

### 4.1 接口缓存使用示例

> 用于缓存查询类接口的返回值，减轻服务器负载。
>
> 缓存注解必须作用在被Spring代理的业务Bean方法上，因此本示例把`@CacheMethodResult`放在Service层，Controller只负责转发请求。
>
> 示例代码如下所示。

* 接口源码`CacheController.java`

```java
package com.pddon.framework.demo.easyapi.cache;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

/**
 * 方法结果缓存示例接口。
 */
@RestController
@RequestMapping("/cache")
public class CacheController {

    @Autowired
    private ProductService productService;

    @GetMapping("/product")
    public ProductDto product(@RequestParam String skuId) {
        return productService.getProduct(skuId);
    }

    @GetMapping("/refreshProduct")
    public String refreshProduct(@RequestParam String skuId) {
        productService.refreshProduct(skuId);
        return "ok";
    }

    @GetMapping("/siteConfig")
    public SiteConfigDto siteConfig() {
        return productService.getSiteConfig();
    }

    @GetMapping("/refreshSiteConfig")
    public String refreshSiteConfig() {
        productService.refreshSiteConfig();
        return "ok";
    }
}
```

* 业务服务`ProductService.java`

```java
package com.pddon.framework.demo.easyapi.cache;

import java.util.concurrent.atomic.AtomicInteger;

import org.springframework.stereotype.Service;

import com.pddon.framework.easyapi.annotation.CacheMethodResult;
import com.pddon.framework.easyapi.annotation.CacheMethodResultEvict;
import com.pddon.framework.easyapi.consts.CacheKeyMode;

/**
 * 方法结果缓存示例服务。
 * <p>
 * 缓存注解必须作用在被 Spring 代理的业务 Bean 方法上；控制器方法本身已被框架切面代理，
 * 因此示例把缓存放在 Service 层。
 */
@Service
public class ProductService {

    private final AtomicInteger productLoadCount = new AtomicInteger();
    private final AtomicInteger siteConfigLoadCount = new AtomicInteger();

    /**
     * keyMode=CUSTOM_ID 时缓存 key = prefix + ":" + skuId。
     */
    @CacheMethodResult(prefix = "demo:product", id = "skuId", keyMode = CacheKeyMode.CUSTOM_ID, expireSeconds = 120)
    public ProductDto getProduct(String skuId) {
        int count = productLoadCount.incrementAndGet();
        return new ProductDto(skuId, "示例商品-" + skuId, count);
    }

    /**
     * 与 getProduct 使用完全一致的 prefix/id/keyMode，才能精确清除对应缓存。
     */
    @CacheMethodResultEvict(prefix = "demo:product", id = "skuId", keyMode = CacheKeyMode.CUSTOM_ID)
    public void refreshProduct(String skuId) {
        // 仅用于演示缓存失效
    }

    /**
     * 方法级缓存：key 直接使用 prefix，不区分参数。
     */
    @CacheMethodResult(prefix = "demo:site-config", keyMode = CacheKeyMode.AUTO_BY_METHOD, expireSeconds = 120)
    public SiteConfigDto getSiteConfig() {
        int count = siteConfigLoadCount.incrementAndGet();
        return new SiteConfigDto("站点配置", count);
    }

    @CacheMethodResultEvict(prefix = "demo:site-config", keyMode = CacheKeyMode.AUTO_BY_METHOD)
    public void refreshSiteConfig() {
        // 仅用于演示缓存失效
    }
}
```

* 返回对象`ProductDto.java`

```java
package com.pddon.framework.demo.easyapi.cache;

/**
 * 商品查询结果。
 */
public class ProductDto {

    private String skuId;

    private int loadCount;

    public ProductDto() {
    }

    public ProductDto(String skuId, String name, int loadCount) {
        this.skuId = skuId;

        this.loadCount = loadCount;
    }

    public String getSkuId() {
        return skuId;
    }

    public void setSkuId(String skuId) {
        this.skuId = skuId;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public int getLoadCount() {
        return loadCount;
    }

    public void setLoadCount(int loadCount) {
        this.loadCount = loadCount;
    }
}
```

> 差异说明：原文档示例的`TestMethodResultParamCacheController`（`getProductBySkuId`/`getProductBySkuInfo`，`id="sku[id]"`）在本模块中不存在，等价接口为`GET /cache/product?skuId=xxx`，缓存注解下沉到`ProductService#getProduct`（`id="skuId"`、`keyMode=CUSTOM_ID`、`expireSeconds=120`）。

* 请求示例（同一个skuId第二次请求`loadCount`不再增长）

```shell
curl "http://localhost:8082/cache/product?appId=webApp&channelId=default&skuId=1001"
curl "http://localhost:8082/cache/product?appId=webApp&channelId=default&skuId=1001"
```

### 4.2 方法查询结果缓存示例

> easyapi还提供了更细粒度的缓存能力，可以为任意一个方法添加结果缓存能力。

* 业务服务`ProductService.java`（方法级缓存，key不区分参数，节选）

```java
    /**
     * 方法级缓存：key 直接使用 prefix，不区分参数。
     */
    @CacheMethodResult(prefix = "demo:site-config", keyMode = CacheKeyMode.AUTO_BY_METHOD, expireSeconds = 120)
    public SiteConfigDto getSiteConfig() {
        int count = siteConfigLoadCount.incrementAndGet();
        return new SiteConfigDto("站点配置", count);
    }

    @CacheMethodResultEvict(prefix = "demo:site-config", keyMode = CacheKeyMode.AUTO_BY_METHOD)
    public void refreshSiteConfig() {
        // 仅用于演示缓存失效
    }
```

* 返回对象`SiteConfigDto.java`


### 4.3 使用缓存管理器手动管理接口缓存

> 当然easyapi提供了使用注解这种业务无侵入式的缓存服务，同样也提供了手动管理缓存的能力。

> 差异说明：本模块未注入`CacheManager`手动读写缓存，原示例的`TestManualManageCacheController`在本模块没有对应实现；实际演示的是通过`@CacheMethodResultEvict`注解失效缓存，对应接口为`GET /cache/refreshProduct`和`GET /cache/refreshSiteConfig`。框架的`CacheManager`手动管理能力仍然可用，只是本模块未提供示例代码。

* 缓存失效方法（`ProductService.java`节选）

```java

     */

    }

    @CacheMethodResultEvict(prefix = "demo:site-config", keyMode = CacheKeyMode.AUTO_BY_METHOD)

```

* 失效接口（`CacheController.java`节选）

```java
    @GetMapping("/refreshProduct")

```
